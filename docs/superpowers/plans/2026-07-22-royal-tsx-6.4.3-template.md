# Royal TSX 6.4.3 Template Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a verified Royal TSX 6.4.3.1000 Chinese template, preserve 6.3 support, and make 6.4.3 the default.

**Architecture:** Keep versioned replacement templates as the source of truth. Extend the existing Node.js entry point with strict manifest parsing and SHA-256 verification before any app mutation, then exercise it through Node's built-in test runner using temporary app fixtures.

**Tech Stack:** Node.js ES modules, `node:test`, macOS `plutil`, Bash, Git

---

## File Map

- Create `tests/royal_chinese.test.mjs`: black-box CLI tests for defaults, manifest validation, replacement, and backup behavior.
- Create `templates/6.4.3.1000/**`: four localized resources generated from the installed 6.4.3.1000 app and existing Chinese translations.
- Create `templates/6.4.3.1000/MANIFEST.txt`: SHA-256 allowlist for the four resources.
- Modify `scripts/royal_chinese.mjs`: select 6.4.3 by default and validate the selected manifest before app writes.
- Modify `README.md`: describe both supported builds and integrity verification.

### Task 2: Implement Strict Manifest Verification

**Files:**
- Modify: `scripts/royal_chinese.mjs`
- Test: `tests/royal_chinese.test.mjs`

- [ ] **Step 1: Add `createHash` from `node:crypto`, allow the test project-root override, and implement `verifyTemplateManifest(templateRoot, sourcePaths)`.**

The parser must accept comment and blank lines, require lines matching `^[a-f0-9]{64}  templates/<version>/<relative-path>$`, reject duplicate/unexpected/missing targets, resolve paths beneath the selected template directory, and compare each file's SHA-256 using `createHash("sha256").update(fs.readFileSync(path)).digest("hex")`.
